# 照着拍 v1.3：手机里的一次完整互拍

2026-10-11，应用版本 0.4.0。承接 [双人协作设计](product-v1.2.md)，保留 [原始 PRD](prd-v1.1.md)。

这次针对三个实际反馈调整：电脑里呈现宽网页而非手机体验；灵感图重复、缺少不同场景；光影等摄影要素藏在高级设置，建议不够具体。

## 手机是主要使用场景

产品仍是无需安装的移动 Web App。手机浏览器全宽呈现；电脑默认呈现 440px 竖屏应用，并提供复制当前体验网址到手机的入口。各页面、编辑弹窗、交接卡、相机和结果页按容器宽度排版，避免窄容器内仍使用桌面栅格。保留暖白、墨绿、浅青绿和照片主导的视觉。

电脑可以浏览与操作；真正互拍应在手机 HTTPS 网页中使用相机。浏览器能力不等于原生系统相机，尤其是暗光、曝光控制和夜景模式。

## 灵感的价值是能执行

移除 8 个复用图片的练习入口，保留 8 张独立参考：窗边咖啡馆、街角遮阳、落日海边、雨后蓝调、花园树影、阴天建筑、山坡侧光、原创油画姿态。新增 4 张图通过图像生成工具创建，详情见 [素材记录](model-assets.md)，不是实际用户试拍照片。

首页卡片显示光线、场景、执行条件和配色；可以按光线筛选，也保留日常、Idol 导入与画作分类。进入参考页后说明这张图值得学的构图或光影关系。所有参考打开后实际运行人体识别，不预填关键点。

## 光影成为主流程

参考页直接提供「这束光，现场怎么找？」。默认仍只跟随构图，动作由被拍者决定；用户主动加入光影，才把用光方案带进此次拍摄。

1. 确认现场有什么光：窗边柔光、日光树影、落日轮廓、阴天漫射、夜景橱窗、傍晚侧光或开放阴影。
2. 看俯视站位图，理解光源、人物与手机的关系。图是编辑的建议位置，不是测量结果。
3. 按「先找到光 → 被拍者站这里 → 拍摄者这样取景」执行。
4. 按需展开明暗、背景景深、动作瞬间和条件限制。
5. 条件不同时换方案。保留构图、动作、镜像和原参考，提示光影效果会不同。
6. 交接卡展示这套方案；相机中可随时查看，关闭后继续拍摄，不抢占实时构图或动作提示。

示例模板默认带编辑推荐方案。个人导入照片不猜定光源，加入光影后必须主动选择现场条件才能确认。未选光影时不出现强制用光提示；已保存的选择可供重新启用。

## 拍后判断与下一张

原片仍可立即保存。选了光影或明暗时，在检测可靠的情况下读取参考与原片各自人物矩形框内的像素，显示亮度中位数在暗到亮刻度上的位置；详情可查看接近黑/白的像素比例。

这是区域像素描述，框内含衣服与背景，不是肤色分割、面部曝光评分、焦点检测或美学分数。刚拍的照片没有可靠人物范围时不生成数值。深色衣物、剪影与夜景不会自动被判为错误。测量不会修改硬件曝光。

「脸太暗或太亮」展开当前用光方案的具体建议，并能回到参考页换方案。原有「人物小一点／大一点／更多背景／动作自由」仍实际更新下一张目标，并保留用光方案。

调色区域可主动试用原参考场景的编辑预设，继续调冷暖、明暗、对比与强度；可恢复、独立导出，原片始终保留。预设不是自动风格迁移，也不改变光源方向。

## 明确边界

- 真实运行：本地人体检测、构图和有限手臂指导、拍照保存、人物框像素读取、拍后调色。
- 编辑方案与用户确认：光向、软硬、找光与站位、背景、机位、时机、调色预设。
- 尚未实现：实时光源方向识别、自动硬件曝光/对焦、真实重打光、精确景深或焦距反推。
- 可选云端解读代码保留，凭证仍未配置，任意照片的复杂光影自动分析尚未接通。

没有新增依赖或改动部署方式。手动托管的网站需重新上传 v0.4 的整个解压文件夹；更新 GitHub 不会自动替换网站。

下一轮真机互拍应验证：两个人能否凭站位图找到光、替代方案是否符合现场、拍后对照是否帮助决定重拍；继续记录手机性能与浏览器能力。
