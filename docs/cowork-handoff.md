# 照着拍：给其他 AI Coding / cowork 应用的交接说明

更新：2026-10-12。目标是做出可使用的手机拍照辅助产品，保持同一套交互的两种视觉；不是只复刻一张静态首页。文档、源码和截图是需求与实现参考，实际是否支持相机、模型和文件保存要按目标平台验证。

## 1. 先交付什么

完整前后端版和纯前端版各自保留 A 杂志版、B 笔记版。同一套功能规范与数据协议，不以删功能来制造风格差异。当前仓库已有双风格产品和可选 Node 后端，尚未整理为两个独立的架构源码项目。历史静态体验 ZIP 是部署成品，不等于独立纯前端开发源码。

如果 cowork 只有前端能力：先完成双风格前端，保留所有本地可行功能；云端图片分析通过可配置的外部后端接入。没有后端时明确显示未配置，提供手动选站位和标注示例；不把固定湖边示例当作用户图片分析，不在网页中放付费模型密钥。外部服务需要额外实现域名授权、CORS 和滥用限制；当前 API 按同源部署设计，不能声称已经支持任意域名。

## 2. 用户与痛点

核心人群为二三十岁的都市女性，以及同行的朋友、伴侣、家人。双方缺乏摄影专业知识；收藏了好看参考图，但无法把它变成“手机怎么拿、人物站哪里、动作怎么做”。遇到好看风景时不会把人放进画面；拍摄中同时讲很多抽象术语导致沟通挫败；拍完仍不知道下一张只该改哪里。

现有证据是需求提出者在原型体验中的反馈（N=1），不是经过验证的市场统计：偏好精致图片；“易用性很差”；名字晦涩；看不见上传入口；应服务手机使用；需要同时指导两个人。先验证新手能不听讲解完成拍摄闭环，不杜撰转化率、留存或真实用户采访。

## 3. 核心任务与 9 个页面

底部四个入口：开始拍、找参考、收藏、我的拍摄。以下是逻辑页面名称，不要求框架复制内部状态名作为 URL。

| 页面 | 关键操作 → 去向 |
|---|---|
| 开始拍 | 30 秒上手；拍眼前风景 → 风景输入；上传参考 → 拍摄方案；怎么用 → 当前风格手册 |
| 找参考 | 分类/场景/搜索；点击卡片 → 参考详情；当前分类上传 → 保存个人参考并直接进入方案 |
| 参考详情 | 看原图与两人提示；收藏；照着拍 → 拍摄方案 |
| 风景输入 | 拍摄/上传空风景；明确同意发送后请求 AI → 场景方案；未配置/失败 → 手动继续；示例明确标注 |
| 拍摄方案 | 选人景平衡、多留风景、突出人物；人物虚线范围随方案变化；两角色说明；开始拍 → 相机；高级设置按需展开 |
| 拍摄相机 | 请求手机权限；优先指导取景，再指导动作；手动拍摄 → 照片结果；权限/遮挡/多人时说明并恢复 |
| 照片结果 | 原图/对比；下一张只改一项 → 保持目标重拍；下载原图；调色为单独导出；保存记录 → 我的拍摄 |
| 收藏 | 参考收藏与个人参考；编辑名称、分类；确认删除；不连带删除已保存拍摄记录 |
| 我的拍摄 | 本机记录，恢复目标继续拍；下载/删除；跨设备同步不属于当前已实现能力 |

主链路 A：开始拍 → 上传风景 → 同意 AI 分析/手动选择 → 选构图 → 两人分工 → 相机 → 结果 → 改一点重拍/保存。

主链路 B：找参考/当前分类上传 → 详情或直接方案 → 明确喜欢构图、动作、氛围中的哪些 → 两人分工 → 相机 → 结果。

每个分类都要有明显上传入口：全部/日常人像“上传我的参考图”，同款打卡“上传想拍的同款”，画作复刻“上传想复刻的画作”。上传后不先强迫填表；个人参考支持持久保存、重命名、分类和删除。内置参考包括日常、明星热门动作/场景打卡、经典画作复刻。未知打卡地点不得伪造认证。

## 4. 拍摄现场的分工

拿手机的人：拍摄方向、画面比例、留白、水平线、人物大小和取景调整。被拍的人：站位、身体朝向、动作和视线。不能只有姿势卡片而没有摄影者指令。

屏幕优先显示原图/构图示意、两人各一条行动提示、开始拍按钮。实时提示一次只给一项；构图错误先修构图，遮挡或人不在画面时停止动作匹配。虚线框是二维构图位置，不是现实距离测量，也不是检测出的真实人物。

光线保留为独立可用能力：识别或说明不确定性，提供面向光源、避开顶光、逆光/侧光等现场建议；视觉模型无法确认时不要强行填光型。曝光、焦距、对焦和灯位只提供建议，未经浏览器硬件能力证明，不宣称能直接控制手机相机。

## 5. 两种视觉方向

| A 杂志版 | B 笔记版 |
|---|---|
| 纸白 #f7f5ef；墨绿 #273f35；柔绿 #e9edde；衬线标题和充分留白 | 白色 #ffffff；珊瑚红 #f04457；浅粉 #fff1f2；无衬线、图片卡片和清楚的操作层级 |

只做手机主体验，建议按 390px 宽设计并覆盖 360～430px。电脑打开时展示手机宽度预览；不用做桌面侧栏。参考图片要丰富、美观，覆盖咖啡馆、城市街角、建筑、书店、旅行湖海、草地、夜景等。素材来源、AI 示例和历史原图要清楚；未经核验不能写成明星官方打卡点。A 不叫“暖色版”，B 参考笔记型内容产品的熟悉交互，不使用他人品牌标识。

首页要有可执行的 30 秒上手提示，以及固定“怎么用”入口。用户手册分别跟随 A/B 视觉，面向普通用户，不夹带 Node、HTML 上传、部署或 API 密钥说明。PRD 面向负责人、研发、算法：讲痛点、证据、状态、模型输入输出、异常恢复；用交互设计图解释方案，截图仅证明现状。

## 6. 模型与数据

当前选择：火山方舟 `doubao-seed-2-1-pro-260915`；接口 `https://ark.cn-beijing.volces.com/api/v3/responses`。模型及账号权限来自需求提出者的控制台信息。API Key 不在交接材料中。

后端 GET /api/health 只检查配置；POST /api/scene 分析风景；POST /api/interpret 理解参考。两种 POST 都需要明确授权。图片长边约 1024px / JPEG 0.82；输入 dataURL≤3,000,000 字符；请求体≤3.5MB。Responses 输入包含 input_text、input_image；非流式、关闭思考、JSON、store=false。只读 completed 状态下的 assistant/output_text，忽略 reasoning；结果经过业务 schema 校验。超时 20 秒，无自动重复收费重试。真实模型效果、耗时与费用尚待产品内验收。

风景返回 summary、light（style/advice/evidence）、variants（三个唯一 id: balanced/scenery/person，box 归一化坐标及 camera/subject/why）、limitations。人物高度 scenery < balanced < person；框必须在图中；不编现实米数、坐标、地点、身份或不可见安全地面。参考返回 draft、insights、explanation，不凭空生成缺失身体关键点。完整约束参照源码 server/schema.ts 和 src/product/scene.ts。

实时姿态检测使用浏览器本地 MediaPipe，云端不接收每帧相机视频。照片与参考以 Blob/IndexedDB 保存，现有上限为 24 张个人参考、12 条拍摄记录；存储失败仍能用当前照片继续拍，明确提示。取消/返回应释放相机与资源；迟到的检测/模型响应不能覆盖用户已确认的选择。

## 7. 验收：至少跑通这些事

1. 新用户能看懂首页，选择一条主链路并完成拍照，不靠隐藏入口或摄影术语。
2. 三个分类均能上传自己的图片，进入方案；刷新后个人参考仍在，可编辑删除。
3. AI 未配置、调用失败、超时、无效返回时保留原图并能手动继续，示例不冒充分析。
4. 相机申请权限；拒绝、切镜头、遮挡、多人、退出恢复有清楚状态；不凭空画真实检测。
5. 导出原图无引导线；重拍保留参考和计划，只改用户选定的一项。
6. 两种风格功能一致，手机无横向溢出；手册与对应风格匹配。
7. 真实 API 调用与真机验证单独记录，自动化/模拟响应通过不代表云端模型已经可用。
