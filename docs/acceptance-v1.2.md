# 照着拍 v1.2 验证记录

日期：2026-10-11。应用版本 0.3.0。定位和取舍见 [产品设计](product-v1.2.md)。

## 本轮改动

- 首页说明双方分工；默认选择构图，动作自由；最多两个快捷重点，精细编辑按需展开。
- 新增同一张拍摄目标卡，明确手机交接；主动确认后才开启相机。
- 构图调整优先于动作；提示明确面向拍摄者或被拍者；按需语音播报并在退出/切换/拍摄/后台时停止。
- 拍后反馈写入新的目标版本，改变下一次构图框或关闭动作约束；保留其他目标，回到编辑页仍然保留调整。
- 延续原视觉风格；桌面与 390×844 手机布局，优先保证目标卡与快门可操作。

## 验证范围

使用本机 Chromium、真实 MediaPipe 模型和测试专用 Canvas MediaStream。语音集成用浏览器 API 测试替身验证主动触发与停止，没有将这些测试当成手机上真实相机或语音效果验收。

## 本机结果

- `npm test`：48 项规则与后端测试通过，包含反馈使用实际测量范围、保留其他条件、镜像、边界限制、构图优先和动作自由。
- `npm run build`：TypeScript 和 Vite 生产构建通过。
- 将 v0.3 ZIP 解压到独立目录，校验首页位于最外层及 16 个构建文件 SHA-256；用独立静态服务器运行，17 项浏览器流程全部通过。没有依赖 Vite 开发服务或 Node API；配置云端的用例明确使用 HTTP 测试替身。
- 单独的开发环境模型探测用例已通过：四张真实示例均实际运行 MediaPipe，空白图不会生成虚构人物。该用例通过源码导入探测器，不在静态生产测试中重复执行。
- 390×844 手机视口验证目标卡、相机快门、反馈后再次拍摄可操作，页面没有横向溢出；检查首页、目标页、交接卡、相机和结果截图。
- HTTPS/HTTP 页面默认隐藏本地文件提示。云浏览器以 `ERR_BLOCKED_BY_ADMINISTRATOR` 拒绝原生 `file://` 导航，所以本地双击入口未在这台机器进行真实浏览器验证；提示逻辑另用受控协议分支验证，不能代替用户 Mac 上的实际打开。

语音测试只验证浏览器接口调用和停止，不验证设备的中文发音与音量。拍后人物范围来自最近的视频帧近似，并非额外的成片分割。

云端模型仍未配置；现有 Netlify 站点由用户手动上传维护，更新仓库和 ZIP 不会自动替换已部署网站。当前环境对该 Netlify 域名的网络访问受限，因此本轮没有核实线上站点。实际 iPhone/Android 相机、中文语音和真实搭档试拍仍待验证。
