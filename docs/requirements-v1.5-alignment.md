# 照着拍 v1.5：需求对齐与续作任务

状态：用户已认可整体方向，并要求在 5:46 开始实施。实现任务已记录；当前工具无法创建定时唤醒，因此没有实际定时任务。尚未修改应用代码或发布新版本。

## 已确认的需求

- 同款打卡：明星、爱豆、博主及热门照片的地点、场景、动作复刻。提供可浏览的参考内容与具体拍法，导入个人参考作为补充。
- 画作复刻：构图、动作、服装道具、背景、光影与色彩共同表达原作；允许只借用其中一部分。分类用“画作复刻”，页面表达可以是“把自己拍进这幅画里”。
- 产品同时服务拍摄者和被拍者，明确分配取景、站位、动作和按快门的任务。
- 用户明确要求两个版本同步修改：暖色版和笔记版使用相同的功能、操作步骤、按钮文案、引导和错误反馈，只在视觉表达上有所区别。既有作品、分支和 ZIP 另存保留，不能只改其中一版。
- 首页必须提供产品引导或手册入口，帮助普通用户理解用途并快速开始。具体形式建议为简短上手卡片、可操作示例、可再次打开的简短手册，待本轮对齐。
- 易用性与命名是本轮优先问题：减少晦涩名词、前置必要说明、让每个按钮明确表达下一步，不依赖用户读长篇手册才能操作。
- 用户新增选图要求：图片更丰富、更好看，面向二三十岁都市女性、熟悉小红书内容的用户。选图是独立的产品工作，两版使用同一批精选素材，不能仅调整界面颜色而沿用单调的图库。

## 本轮新增、待用户对齐的方案

### 现场人景合照

用户到了海边、山景、建筑、花园等地方，想把朋友拍进去，但没有参考图。拍一张空景或导入刚拍的照片，视觉模型分析可见景物、构图空间、画面边缘与光线线索，提出适合的人景构图。

输出应首先可视化：在原现场图上叠加建议人物位置与大小，明确这是示意，附上两个人的简短指引。默认推荐一个“人景平衡”方案，可切换“多留风景”或“突出人物”。不用先填写摄影参数或选择很多偏好。

单张照片不能可靠推断地面距离、现场三维坐标或相机型号。人物占比使用画面相对坐标，进入相机后根据真实人物范围修正取景，不编造精确几米或镜头焦距。

这个功能需要视觉模型 API。当前 v0.5 的“手选现场光线后匹配编辑参考”并未实现现场照片分析。无配置或调用失败时，明确显示原因，提供重试与手选拍法，不伪装成成功的 AI 结果。

### 信息架构与可读性

建议底部 4 个带文字的 Tab：开始拍、找参考、收藏、我的拍摄。默认打开“开始拍”，主页突出两个实际任务：“拍一下眼前的风景”“导入想照着拍的照片”；浏览参考提供清楚的次级入口及底部“找参考”。分类不是用户必须先理解的步骤。

灵感页的分类：全部、日常人像、同款打卡、画作复刻。咖啡馆、街头、海边、夜景等作为场景筛选，避免和底部导航混在一起。

每个主要步骤给出明确标题与主要行动；首次拍照只需输入图片、确认方案、开拍。高级选区、镜像、动作约束与调色作为可选操作。拍摄时只强调当前该行动的一方，不同时让两人读一大段文字。

9 页是全产品的信息结构，并不要求用户依次走完 9 页。常用流程仍为“选现场或参考照片→看这张怎么拍→打开相机”；拍完进入结果。增加 Tab 或手册本身不算完成易用性改善。

### 首页引导与产品手册草案

首次使用在首页直接展示简短上手卡片，不用全屏教程挡住任务入口。看过后可收起，顶部保留“怎么用”，以后随时打开。两个视觉版本使用同样的示例与教学内容。

引导标题：不知道怎么拍？从一张照片开始。

说明：拍一张眼前的风景，或者选一张想照着拍的照片。照着拍会告诉拿手机的人怎么取景，也告诉镜头前的人怎么站、怎么动。

三步示例：选一张照片→看人物位置示意和双方提示→照着提示拍，拍完只改不满意的地方。使用“现场原图、建议人物位置、拍摄结果”三幅图解释，而不是让用户先认识功能名词。

次级动作“看一个示例”：示例演示应有明确示例标识，不冒充实时相机或 AI 调用。可操作地体验如何选图、看拍法、理解双方提示，结束后能直接开始自己的拍摄。

“怎么用”短手册需覆盖：如何拍现场、如何导入参考、如何找同款和画作、两个人分别看什么、怎么重拍、下载照片和保存这次拍摄的区别、常见权限与加载问题。逐条给截图及操作位置，不呈现长篇产品介绍。首屏上手不依赖读完整手册。

### 易用性验收目标

- 首页第一屏能看懂用途、找到拍现场和导入参考两个入口；用一句话区分拍摄者和被拍者。
- 每个步骤都有主要按钮，按钮表达操作结果；返回保留上下文、输入失败有原因及重试。
- 选择参考后直接获得可用拍法，不强迫填写摄影参数、选择全部目标或完成复杂问卷。
- 手机可读字号、足够对比度及明确按钮文字；核心提示不靠很小的英文或图标解释。
- 新用户能通过示例理解完整流程；实际是否好用仍需首次使用体验验证，不能只以技术测试通过代替。
- 暖色版与笔记版用同一组任务和交互做比较，减少功能差异对视觉选择的影响。

### 图片与参考内容的筛选标准

面向目标用户的审美方向为选图假设，不声称所有都市女性都喜欢同一风格。兼顾自然日常、胶片街拍、清爽都市、旅行人景和复古表达，允许分类浏览。

- 场景丰富：咖啡馆、城市街道、展馆与建筑、花园公园、海边山景、雨天和夜景。避免几乎都是相同咖啡馆、相同脸型、相同近景坐姿。
- 构图丰富：近景、半身、全身、人小景大；坐、站、走、回头等不同动作。光影包含柔光、日光、阴天、逆光与夜间灯光。
- 画面选择：真实、自然但有取景和光影设计；允许清晰、胶片、闪光和复古等不同处理，避免过度磨皮、统一滤镜、塑料质感和不合理人体细节。
- 可执行：每张图有明确值得参考的地方，并能写出普通手机拍摄者可以尝试的机位、动作和光线建议。高门槛布景、服装或道具应在参考详情中注明，不把它们当成用户默认具备的条件。
- 来源准确：同款打卡优先整理真实原图、出处与已确认地点，不把生成示例当作真实明星或博主打卡照片。画作复刻展示原作，真人演示作为独立参考，并说明来源。补充生成示例时清楚标注。
- 首批可按约 24 张精选参考规划：日常人像约 12 张，同款打卡约 8 张，画作复刻约 4 张；数量为初始目标，质量与来源优先，实际数量待选图后确定。
- 两版共用图片和内容；保持各自的排版与配色。移动端列表缩略图清楚、裁切不截断关键动作，详情页能看清完整原图；避免大量大图导致首屏长时间空白。

实施前先整理选图清单和可查看的参考墙，说明每张图的来源、风格、关键拍法与使用难度，供用户评估审美方向。此轮仅保存筛选要求，没有声称已经找到或下载这批图片。

## 建议的新结构：9 个主要页面

| 编号 | 页面 | 主要交互与去向 |
| --- | --- | --- |
| P1 | 拍照首页 | 拍现场→P4；导入参考→系统选择图片→P5；找灵感→P2 |
| P2 | 灵感列表 | 分类和搜索在本页筛选；点图片→P3；收藏图标在本页切换收藏状态 |
| P3 | 参考详情 | 收藏不跳页；照着这张拍→P5；同款打卡的已确认地点可打开外部地图；返回→原列表位置 |
| P4 | 现场照片 | 拍摄或导入空景，重拍/换图停在本页；使用这张现场图→发送确认→本页分析状态→P5；取消返回入口 |
| P5 | 拍摄方案 | 切换人景占比方案、现场取舍与动作在本页更新；图片调整→编辑弹窗→回P5；保存方案留本页；确认并开拍→首次交接弹窗→P6 |
| P6 | 指导拍摄 | 快门→P7；调整方案→P5；看上一张→P7；参考、辅助线、用光说明、动作下一步、语音、前后相机都在本页操作 |
| P7 | 照片结果 | 再拍→P6；保留偏好+一个调整→预览修改→P6；调整方案→P5；导出原片/成片/对比图停在本页；保存拍摄小卡留本页；结束拍摄→P9 |
| P8 | 收藏 | 点收藏参考→P3；取消收藏留本页；空状态去找灵感→P2 |
| P9 | 我的拍摄 | 保存的参考+方案+结果；继续拍→恢复P5；查看结果→P7；删除→确认弹窗→本页；开始新的拍摄→P1 |

P1、P2、P8、P9 是底部导航对应的页面。系统权限提示、手机相册、外部地图、加载和错误状态不额外计算为产品页面。三个入口共用 P5、P6、P7，无需做三套重复相机。

## 辅助交互：5 类弹窗

1. 图片编辑：裁切、旋转、参考人物确认。空景输入只需裁切，不要求框出不存在的人。涂抹动作仍为参考方案中的可选精细调整。
2. 首次手机交接：分别显示双方任务；“我来拍，打开相机”→P6；“修改方案”→P5。直接重拍和小修改不重复交接。
3. AI 发送确认：说明发送当前照片用于分析；同意后分析，取消返回当前步骤。不得自动上传相机视频。
4. 重置/离开确认：换图、改变裁切或方向需要重新确认目标；有未保存拍摄时返回首页应提示保存/继续离开/取消，避免悄悄清空。
5. 删除确认：删除指定拍摄小卡，取消保留。取消收藏是即时可逆操作，不要求弹窗。

光影细节、动作与镜像开关、调色和反馈预览是页内展开，不再变成一层层导航。所有返回操作保留可继续的上下文；刷新恢复只承诺明确保存的小卡。

## 各入口默认重点

- 日常人像：构图与光线，动作自然。
- 同款打卡：参考中有辨识度的动作、构图和背景；地点信息来自确认的内容资料，不能靠照片猜地址。
- 画作复刻：构图与光影，列出可选道具和姿态提示，不强制全套布景。
- 现场人景合照：景物完整、人物位置和占比、光线，以及不遮挡关键景物的动作。

## 技术与验证要求，供后续接着做

- 区分“现场建议人物框”和“照片中实际检测到的人物框”。空景不能产生伪造的人体检测、姿势骨架或人物亮度测量。
- 不沿用个人参考导入后必须确认人物的流程处理空景。需要独立的输入与目标数据来源。
- 模型只返回可验证的构图与拍摄方案结构，服务端校验坐标、枚举、长度、输入大小、超时和取消；密钥留服务端。
- 现场输入图中没有人时，不能把背景区域亮度当作参考人物亮度。既有 LightReview 需按来源处理。
- 相机仍基于实际视频检测指导构图；动作脚本和光线建议标清人工执行。即使模型失败也保留用户上传图与原方案。
- 保存真实 Blob、方案来源和拍摄目标快照，正确释放会话 URL；增加新模型字段时保持原小卡可恢复。
- 重点验证：新用户三条入口；现场无人物照片；模型未配置/失败/取消；返回与换图；一改再拍；本地保存刷新；两套视觉版本及静态体验包。
