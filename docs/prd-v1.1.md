# 照着拍｜产品需求文档
版本：v1.1  
更新日期：2026-10-11  
状态：开发需求基线，模型效果与设备兼容性待验证

## 1. 产品概述
### 1.1 定位
读懂一张参考照片，带用户拍出自己的作品。
用户从模板或手机相册选择参考，涂抹想复刻的动作，或选择整张图复刻。系统生成可编辑的拍摄解读，并将用户确认的目标转为拍前准备、实时指导和拍后处理。

### 1.2 核心问题
用户已经知道喜欢哪张照片，但缺少执行方法：人物如何摆、手机如何取景、现场需要什么光线、哪些效果依赖拍后处理。看参考与切换相机反复进行，仍难确定下一步。

### 1.3 用户与场景
|平行场景|用户目标|参考来源|
|---|---|---|
|Idol 同款|模仿喜欢的动作与画面|手机收藏、截图|
|名画再演|体验经典人物姿势与视觉效果|精选模板或个人参考|
|日常灵感|拍摄人像、街拍、旅行作品|模板、收藏照片|
|自定义参考|复用自己的照片或任意喜欢的参考|手机相册|

以上为需求假设，须以用户实际试拍验证。追星不设为唯一主场景。

### 1.4 交付形态
移动端优先的独立 Web App，提交 GitHub 源码、HTTPS 体验链接、运行说明和真实演示视频。商业上架、完整原生相机能力不属于本次交付。核心体验无需登录。

## 2. 目标、指标与范围
### 2.1 目标
G1：用户携带自己的参考图完成选择、解读、指导、拍摄、保存。
G2：用户理解并控制复刻范围，修改解读会改变实际目标。
G3：主要摄影要素均有明确的分析位置与执行方式。
G4：实时功能来自实际检测，支持程度和失败状态透明。

### 2.2 观察指标
参考导入成功率、目标确认完成率、拍摄保存完成率、首次操作耗时、误选与指令理解错误、参考切换次数、重拍次数、满意度及再次使用意愿。
测试同时记录设备、网络、参考类型和已支持能力。首轮建立基线后再设提升目标，不虚构增长数字。

### 2.3 优先级
P0：首版必须完成；P1：核心闭环后扩展；P2：理想态探索。
|编号|功能|优先级|
|---|---|---|
|R01|模板浏览与手机相册导入|P0|
|R02|涂抹/点选动作、整图选项|P0|
|R03|主要摄影要素的参考解读、编辑与确认|P0|
|R04|真实相机、实时构图与一种有限姿势指导|P0|
|R05|拍前条件建议、相机权限及失败恢复|P0|
|R06|拍照、对照、原片保存、重拍|P0|
|R07|主体明暗与清晰度检查、设备支持的控制|P1|
|R08|基础参考色调调整与效果导出|P1|
|R09|更多姿势、细微表情与手部模型|P2|
|R10|视频自动构图、同款运镜、今昔重拍|P2|

“全部要素纳入”指分析与执行路径完整，各要素自动化程度不同。P0 中曝光、焦点等提供参考解读与拍前建议；实时测量和控制按 P1 实现并验证。未实现能力不得显示为可实时执行。
不包含：社区、点赞关注、登录付费、任意舞蹈教学、生成式重打光。

## 3. 摄影能力矩阵
|要素|参考分析输出|执行方式|首版能力边界|
|---|---|---|---|
|姿势|部位、相对位置、可见关节|实时轮廓与有限动作指令|仅验证动作；遮挡暂停|
|表情|可观察表情示意|拍前/拍摄参考|无精确微笑评分|
|构图|画幅、人物位置占比、留白|实时位置与大小对齐|P0|
|机位/透视|可判断的视角特征|拍前示意与建议|不反推准确距离、焦距|
|光影|明暗分布、软硬与可能方向|找光、站位建议|标记推断；实时光向暂不做|
|曝光|主体和背景明暗效果|P0 建议；P1 明暗检查及设备控制|不把深色风格判为错误|
|焦点/景深|主体清晰、背景虚化特征|P0 建议；P1 清晰度检查和可用控制|图像模糊不等同焦点失准|
|色彩/白平衡|冷暖、主色、对比风格|P0 解读；P1 拍后基础调色|不改变真实光源方向|
|背景/造型|环境、服装、道具条件|用户准备清单|不自动补全现场|
|动作瞬间|静止、抓拍、运动模糊特征|拍摄建议|不承诺精准快门控制|

每项输出含证据、置信程度与支持标签：实时指导／拍前建议／拍后处理／仅参考。未知项允许返回“不确定”，不强行填写。

## 4. 信息架构与任务流程
页面：P01 灵感首页→P02 参考编辑与解读→P03 指导相机→P04 成片结果。
流程：
1. 选择模板或从手机相册导入。
2. 预处理图片，确认目标人物。
3. 涂抹所需动作，或选择整张图复刻。
4. 查看自动解读，选择其他摄影要素，修改并确认。
5. 查看拍前准备，进入相机。
6. 接受已支持的实时指导，自行按快门。
7. 查看参考与成片，保存或重拍。

所有输入改变均使依赖旧输入的目标失效；确认后的目标作为拍摄唯一依据。

## 5. 页面交互需求
### 5.1 P01 灵感首页｜R01
平行分类：日常灵感、Idol 同款、名画再演；固定可见入口“从相册选参考”。模板卡显示示例与能力标签。选择进入 P02。
首批计划 12—14 张卡片，其中精做 4—6 张；示意模板不得伪装为实时模板。素材来源与许可记录完整，个人上传图片不进入公开库。

### 5.2 P02 相册导入｜R01
点击调用系统图片文件选择器，允许手机相册及桌面文件选择，不强制打开相机。一次选择一张。取消保留已有状态，错误可重选。
基础支持 JPEG、PNG、WebP，初始限制 20MB（实现初值，测试可调整）。检查内容及解码结果，修正方向并降采样分析；HEIC/HEIF 单独验证，失败提示使用 JPEG/PNG 或截图。
提供预览、必要旋转与裁剪。几何修改后重建坐标与分析，旧选区失效前提示用户。

### 5.3 P02 选择复刻范围｜R02
默认轻涂模式，文案“涂一下你想学的动作”。支持点击快速选择；半透明笔迹、高亮关联部位、笔刷大小、擦除、撤销重做、清空。单指绘制、双指缩放移动，避免滚动冲突。
根据整图关键点匹配笔迹命中的关节或线段，再扩展必要动作组。如选手腕，需要肩肘腕及头肩参照。选区负责表达范围，人体识别负责提供动作目标。背景涂抹提示无可指导人体部位。多人物先点选一个，不混合目标。

一键“整张图复刻”关闭涂抹编辑但保留笔迹，切回恢复。整图包含构图及支持的姿势；背景、光影、色调等在下方作为可选参考要素，不承诺全部自动重现。

部分模式按身体尺度比较关节与相对向量，允许背景、人物位置和大小自由。整图模式增加图像坐标中的人物位置占比约束。镜像复刻提供明确切换，不擅自反转。

### 5.4 P02 可编辑解读框｜R03
停止涂抹后防抖分析，自动生成解读。显示“已选动作”与“其他摄影要素”：
- 已选动作：所选部位、参考动作、拟指导范围、支持标签。
- 其他要素：构图、机位、光影、曝光、焦点景深、色彩、背景造型、动作瞬间；可展开查看证据与建议。

部分模式默认仅跟随所选动作；其他要素可勾选。整图默认跟随构图和支持姿势，其余要素供用户选择。用户未选的要素不参与匹配、不生成强制纠正。

支持直接修改解读文字、“重新解读”“恢复自动解读”“确认目标”。示例：“只学抬手，不要手贴脸；保留参考的暖色，背景自由。”
系统重新解析为结构化目标，展示更新的高亮和摘要供确认。删除部位、取消约束、改变要素必须改变实际指导。超出能力请求明确提示，保留输入并允许修正，不静默继续旧目标。
编辑时暂停自动覆盖；新笔迹改变范围后要求重新确认。参考解读与用户修改分别保存，可恢复。
状态：待分析、分析中、可编辑、解析中、待确认、失败。只有有效配置才可进入拍摄。

### 5.5 P02 拍前准备｜R05
确认后给短清单：所需背景/道具、光线条件、建议视角等。区分图中可见证据与推测。无法满足时用户可关闭相应要素，重新确认目标。
按进入拍摄动作请求相机权限。图片云端分析前明确说明发送数据与用途，用户主动触发；不同意可使用标注清晰的本地受限模式。

### 5.6 P03 指导相机｜R04、R07
界面：真实取景、参考小窗、当前目标轮廓、单条主要提示、快门、前后摄切换、轮廓开关、返回编辑。可选语音不阻塞核心流程。
目标丢失/低置信/遮挡优先；其次整图构图，再有限姿势。平滑、迟滞与保持时间经过真机调优。只呈现可靠且当前相关的指令。
区分对象：“人物往画面右侧一点”与“让人物在画面里更大一些”。箭头表达图像目标，不能把镜头移动方向等同人物画面方向。
用户可随时按快门；首版手动拍摄。

P1 明暗检查按选定目标与主体区域判断，不能用全图平均亮度直接决定曝光好坏。清晰度检查只能提示可能模糊，不武断认定失焦。
通过设备能力查询决定曝光、对焦等控制是否显示。没有接口则给建议，不显示无效控件。禁止把调亮画布伪装成相机曝光调整。镜头倍率仅显示实测支持项。

### 5.7 P04 成片结果｜R06、R08
显示原片及参考对照，支持保存原片、再拍一次、返回改目标、更换参考。保存画面不带骨架和提示；对照图单独可选导出。
P1 色调处理提供效果预览、强度调节、恢复原片、导出效果图。曝光/对比/冷暖处理不能恢复已丢失细节，不标注为真实重打光。处理失败保留原片。
手机保存提供下载；系统分享按浏览器支持展示，不承诺直接写入所有设备相册。

## 6. 状态与异常规则
|状态/事件|系统响应|恢复方式|
|---|---|---|
|选图取消、格式不支持|保留原状态，解释原因|重新选择|
|无人、多人、关键部位遮挡|不生成虚假目标|选人、改选区或换参考|
|模型/API 失败|显示失败，不生成假解读|重试或明确受限模式|
|用户改动未解析|目标待确认，暂停开始拍摄|解析并确认或恢复|
|相机权限拒绝|说明授权方式|重试或返回参考|
|实时人体丢失|清除旧匹配状态、暂停指令|重新入镜|
|设备不支持参数|隐藏不可用控件、提供建议|继续其他指导|
|性能不足|降检测频率并说明|关闭部分能力或退出|
|保存失败|保留结果|重试下载/分享|
|云端请求超时|可取消；旧响应不得覆盖新输入|重试|

## 7. 模型与实现架构
### 7.1 分工
多模态模型：参考图理解、摄影要素解读、用户文本解析。
端侧人体模型：参考与实时人体关键点。
图像检测/规则：明暗、清晰度、目标比较、稳定指令。
相机接口：实际支持的控制与拍摄。
拍后处理：基础调色，不依靠生成式编辑才能完成核心闭环。

参考深度解读候选 Gemini 3.1 Pro Preview（gemini-3.1-pro-preview）；默认流程候选稳定 Gemini 3.8 Flash（gemini-3.8-flash）。官方 API 已列出，但账号权限、区域、费用、限流与实际效果需要联调。不能宣称摄影任务 SOTA 已验证。架构提供模型适配层，避免写死供应商。

以相同参考样本评估动作解读准确性、光影证据、参数幻觉、修改目标一致性、延迟及成本后确定默认模型。
API Key 仅存在服务端环境变量，不写入前端、GitHub 或浏览器请求参数。后端校验结构化响应、限制请求大小和超时，模型输出不得直接执行相机参数。

### 7.2 处理链路
参考图片+选区+可用关键点→云端解读→结构化配置校验→用户修改/确认→实时检测和规则→指导→拍摄。
实时每帧不调用大模型。按用户触发请求解读或复查，避免云端速度阻塞预览。
选区识别与语言模型可组合；语言描述不能替代精确关键点。

### 7.3 数据结构
Reference：来源、尺寸、方向、选中人物、资源许可。
Selection：笔迹归一化坐标、模式、关节组、镜像偏好。
Interpretation：自动文本、用户文本、证据、置信、选中要素、解析状态。
Target：动作目标、构图目标、建议清单、控制意图、能力标签、版本。
Capture：设备能力、实时检测、指导状态、原片、效果版本。
目标配置区分可测量约束与语言建议，不把推断焦距等作为硬规则。

### 7.4 Web 技术要求
TypeScript；参考 IMAGE 推理，实时 VIDEO 推理；候选 MediaPipe Pose Landmarker。节流/可用 Worker 避免阻塞主线程。
HTTPS getUserMedia；正确停止旧轨道、释放相机和资源；处理后台恢复。
参考、笔迹、镜像、object-fit 裁切、视频坐标及保存画幅统一转换。模式/图片/目标版本变化后旧异步结果失效。
兼容清单依据实测，至少检查 iPhone Safari 与 Android Chrome。模型依赖锁定版本，记录许可。

## 8. 视觉与内容规范
暖白画册首页、深绿操作色、暗色取景器与克制轮廓。参考编辑器突出涂抹，解读框逐层展开，避免一次呈现摄影术语墙。提示使用动作语言。
触控目标至少 44px，关键信息不只依赖颜色。人体示意只显示必要部位，不遮住拍摄主体。
模板用自制、获授权或许可明确素材；用户照片不公开。Idol 场景主要支持个人导入。全文不附原型图。

## 9. 隐私、性能与质量要求
默认本地处理实时视频。云端参考分析明确展示发送范围，可取消；不上传连续相机流。临时图片和目标保留周期按实际实现说明，用户可清空。
解读需要提供不确定输出；实时置信不足停止对应建议。
测量预览流畅度、推理间隔、指令更新延迟、模型/API 耗时及连续运行发热情况。依据设备实测制定阈值，不用未经验证的性能数字作承诺。

## 10. 验收标准
|编号|可验证结果|
|---|---|
|A01|手机个人相册图片与模板均能走完整闭环|
|A02|涂抹/点选、擦除撤销、缩放坐标正确|
|A03|选择手部关联正确动作组，背景选择不生成动作|
|A04|部分模式不强制复制整图站位；整图加入构图约束|
|A05|主要摄影要素都有解读或明确不确定状态，标签准确|
|A06|编辑解读改变实际目标；不支持请求可恢复|
|A07|未勾选要素不参与纠正|
|A08|真实相机中移动人物触发真实反馈；遮挡暂停|
|A09|镜像旋转裁切正确，原片不带指导层|
|A10|权限、API、模型与保存失败均可恢复|
|A11|无设备控制能力时不展示假控制|
|A12|原片与调色版可区分，导出可靠|
|A13|客户端和仓库不包含密钥与个人测试照片|

A11、A12 随相应 P1 实现验收；P0 不显示未实现入口。演示必须含个人上传、涂抹、修改解读、真实实时反馈和保存。
用户测试覆盖三个平行场景，对比常规看图拍摄与辅助流程；小样本用于改进，不宣称统计显著或市场需求已证实。

## 11. 理想态与暂缓原因
视频自动构图：固定手机录制，拍后平滑裁切跟随人物，保留原片；受限于出画、画质与编码。
同款运镜：参考视频分段提示手机推进、侧移等；需区分人物运动与镜头运动。
今昔重拍：旧照对齐人物和场景生成对照；需处理透视和场景变化。
精细表情/手指：仅对验证模板扩展，依赖额外检测与遮挡处理。
生成式重打光：独立拍后探索，可能改变面部细节，不能代替现场找光。
舞蹈教学：当前不承诺任意舞蹈动作理解与纠正。

## 12. 开发与交付顺序
1. 相机、端侧人体检测与原片保存。
2. 个人参考导入、涂抹、部分/整图目标。
3. 模型适配后端、摄影解读、可编辑确认。
4. 有限实时指导、异常恢复与模板视觉。
