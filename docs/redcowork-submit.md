# REDcowork：先导入、发布，再按需修改

依据用户提供的作业说明：平台支持 Vibe coding 或代码包上传，只支持纯前端；token 有限，额度耗尽前必须提交作品。优先走代码上传，让平台沿用现有实现，首轮只做发布兼容。没有平台的具体计费规则和剩余额度，不能承诺固定 token 数值。

## 上传材料

首轮只上传 `downloads/zhaozhepai-redcowork-frontend-v0.7.zip`（可独立安装的源码，不是 dist 预览包）。源码位于 `editions/frontend-only/`；包含独立 package.json / package-lock、两种视觉、实际前端交互、图片、本地姿态模型和用户手册。已移除后端、代理、函数部署、密钥配置和后台启动命令。全部云端按钮明确未接入，不产生 API 请求；手动方案、相机、上传、光线建议、本地记录和导出保留。

之前的 18 MB 交接包适合产品重建/评审，首轮不需要再让 REDcowork 全量阅读。原 PRD/截图按需查阅，直接使用代码即可。

## 最短执行步骤

1. 从 GitHub 登录后下载源码 ZIP，进入 REDcowork 的代码包上传入口，导入。若平台限制 ZIP 大小或项目结构，发回实际错误再定向整理。
2. 若平台要求填写构建命令：`npm run build`；发布目录：`dist`。开发命令：`npm run dev`。Node≥22.18 只用于构建前端，不是产品后端。
3. 如果需要给 AI 一条指令，复制代码包中的 `REDcowork-任务.txt`，或下方简版。
4. 预览检查：A/B 风格切换；自己的风景/参考能上传并进入手动方案；相机在独立 HTTPS 页面可请求权限。平台 iframe 是否允许相机还需实测，上传与手动流程始终可用。
5. 拿到作品链接后，先按作业要求提交，再考虑有余量时少量修改。首次导入不让 AI 新生成图片、长 PRD、截图集或整套产品。

## 简版指令

请直接导入附件里的现有纯前端 Vite 项目。首轮只完成安装、构建、预览和发布，定点修复阻塞错误。先读 README.md、package.json，按报错读取相关文件；图片和模型作为静态资源处理。沿用现有双风格、图片、手册与全部前端交互。云端 AI 已明确未接入，保持手动流程。构建 npm run build，发布 dist。检查两种风格及上传进入方案后就发布，返回作品链接；首轮不展开新功能和重构。

报错时只发送：报错原文、实际失败步骤、涉及文件、一个修复目标。构建成功后不要重复跑同一轮检查；先取得可提交链接。
