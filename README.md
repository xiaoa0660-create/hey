# 照着拍

你想要的，一起拍出来。照着拍帮助被拍者与拍摄者围绕同一张照片表达想法、交接手机、执行指导和调整下一张。最新定位与实现见 [手机与用光设计 v1.3](docs/product-v1.3.md)，双人协作基线见 [产品设计 v1.2](docs/product-v1.2.md)，原 [PRD v1.1](docs/prd-v1.1.md) 保留为历史需求。延续暖白、墨绿和摄影大图的视觉风格。

这是 **React 前端 + Node 解读后端** 的 Web App。人体识别和相机画面在浏览器本机运行；可选的视觉语言解读通过后端调用模型。可交互静态体验包和操作步骤见 [打开体验版](docs/interactive-preview.md)；公网地址需要在托管平台完成上传后生成。

## 启动

需要 Node.js 22.18+，本次使用 Node.js 24.19.0 / npm 11.9.0。

```bash
npm ci --cache /tmp/zhaozhepai-npm-cache
npm run dev
```

启动前自动验证模型、复制本地 WASM、构建检测 Worker。前端监听 5173，后端监听 127.0.0.1:3001，Vite 将 `/api` 代理到后端。在**运行服务的同一台电脑**访问 `http://localhost:5173`。云环境的 localhost 地址不能直接当成用户可访问的体验链接。

```bash
npm run build
npm start
```

生产 Node 服务同时提供 `dist` 和 `/api`，默认绑定 127.0.0.1:3001。托管时按平台需要配置 `HOST=0.0.0.0`、`PORT` 并由平台提供 HTTPS。手机真实相机需要安全上下文；同网段普通 HTTP 地址通常不能申请相机。静态体验版可单独托管前端和模型，云端深度解读在该版本中不可用。

`downloads/zhaozhepai-demo.zip` 是 **历史 v0 构图演示**，不包含本次改动。新版含模型、Worker 和后端，不能再用旧单 HTML 打包方式；旧命令会明确提示改用正常应用构建。旧 Pages 发布流程已替换为手动检查流程，未触发部署。

## 可操作流程

应用 v0.4 默认「只学构图，动作自由」。被拍者选一两项重点 → 看双方目标卡 → 交给拍摄者主动打开相机 → 构图优先、按角色逐条指导 → 被拍者反馈下一张只改什么。新的拍后反馈会改变实际取景目标，详细规则见 [产品设计 v1.2](docs/product-v1.2.md)。语音只在点击「读给对方听」后播放，需浏览器支持。

1. 首页选择 8 张独立的原创生成参考之一，可按光线筛选；或导入 JPEG / PNG / WebP（20 MB、3200 万像素以内）。Idol 分类用于导入个人收藏。
2. 裁切、旋转、确认人物；端侧模型识别 33 个关键点。多人参考必须先点选一个人。默认确认构图即可继续，也可以按需加入动作或光线色彩。
3. 在「精细调整（可选）」里涂抹或点击手臂、头部等；支持粗细、擦除、撤销、重做、清空和双指查看。只有命中实际检测部位才创建动作。整图模式保留原笔迹，可切回继续。
4. 查看解读和要素证据，选择实时指导／拍前建议／拍后处理／参考项。可修改文字并应用，例如“只学抬手，不要手贴脸；保留参考的暖色，背景自由”。本地只解析已支持表达，其他内容保留输入并阻止确认；复杂语义需配置云端模型。
5. 确认目标，给双方看交接卡，由拿手机的人主动打开相机。先比较构图，再比较已选的手臂相对肩膀位置，始终只指导一方。没有选择动作就不纠正姿势。无人、多人、过期检测会暂停提示；接近目标须连续稳定检测。
6. 随时按快门，导出没有辅助线的 JPEG 原片；可重拍、改目标、换参考、导出对比图。拍后选择人物大小、更多背景或动作自由，先预览新目标再确认，交接后应用到下一张。基础冷暖、明暗、对比度及强度调整在拍后完成，效果另存，不覆盖原片。

前置预览、推理输入和照片采用同一镜像方向；参考的“镜像学习”单独控制目标姿态。页面隐藏、切换镜头、返回或拍完均停止旧相机轨道。硬件变焦仅在 `getCapabilities()` 确实提供范围时显示，失败保留当前设置。

## 手机与现场用光

手机优先的 Web App；电脑上默认呈现 440px 竖屏应用，手机上占满可用宽度。无需安装原生 App。

参考页直接提供 7 种现场用光方案：窗边柔光、日光树影、落日轮廓光、阴天漫射光、夜景橱窗光、傍晚侧光、开放阴影。启用后确认现场条件，查看俯视站位图及找光、人物、手机、明暗、背景、时机建议；方案保留到交接卡和相机中，可随时打开查看。修改现场用光不改变构图、动作或原参考的色调建议。个人照片没有自动猜定的光源，需手动选择现场条件。

拍后在可靠人物范围内读取真实像素，比较参考与原片的亮度中位数；衣服与背景也在矩形框中，不能当成脸部曝光评分或光向识别。数据不足不显示数字。可主动试用参考场景的编辑调色预设，再调冷暖、明暗、对比与强度，原片保留。

## 可选深度解读

复制 `.env.example` 为 `.env`，只在服务端或托管平台的秘密变量设置密钥。不要把密钥放进 `VITE_` 变量、浏览器代码、Git 或聊天内容。

- `VISION_PROVIDER=gemini`：设置 `GEMINI_API_KEY` 和你的账号可访问的 `VISION_MODEL`。
- `VISION_PROVIDER=openai`：设置 `VISION_API_KEY`、`VISION_MODEL`，可用 `VISION_API_BASE` 指向兼容的 HTTPS 视觉接口。
- 本项目没有假定 PRD 候选模型名已发布或可调用。没有凭证时 `/api/health` 报未配置，界面仍能走本地核心流程。

用户点击“同意发送，开始解读”后才发送：当前裁切参考的 JPEG 缩略图（最长边 1024）、归一化选区、文字和已有目标。**摄像头视频不上传**。服务器不存储参考图片；上游模型服务的数据策略需按选定供应商核对。服务有请求体限制、结构校验、同源检查、单客户端并发限制、20 秒上游超时；模型只能返回有限目标，不得直接执行相机参数。

目前后端适配器与模拟上游测试已完成，**未进行真实付费模型调用**。高级图片内容解读不能当成已经接通。

## 验证

```bash
npm test
npm run build
PLAYWRIGHT_CHROMIUM_EXECUTABLE=/usr/bin/chromium npm run test:e2e -- --workers=2
```

没有系统 Chromium 时先运行 `npx playwright install chromium`，再执行 `npm run test:e2e`。测试会启动开发服务；若已有服务请确认前后端都运行。

测试包括实际 MediaPipe 图片和视频帧推理、选择坐标、双方交接、默认不约束动作、构图优先、语音触发与停止、反馈改变下一张目标、错误恢复、后台停止、镜像、像素级无辅助线原片检查，以及桌面与手机尺寸截图。视频来自测试专用 Canvas MediaStream；**这些不是 iPhone/Android 真机相机验收**。最新记录见 [v1.3 验证记录](docs/acceptance-v1.3.md)。

## 结构与边界

- `src/components/`：四个主页面、参考选区与裁切。
- `src/domain/`：受支持目标、笔迹映射、相对姿势、稳定提示、本地文本解析。
- `src/workers/pose.worker.ts`：经典 Worker 中的 MediaPipe Full 模型推理。
- `server/`：Node API、Gemini / OpenAI 兼容适配、Zod 校验。
- [素材和模型来源](docs/model-assets.md)、[云环境恢复](docs/cloud-start.md)。

坐标以裁切画面的 0–1 归一化位置为准。局部动作相对肩膀和肩宽，不默认约束人物站位和远近；构图使用可见关键点包围框作为人物范围近似，遮挡或姿势差异可能影响占比。检测支持是有限近似，不判断长相、审美、精细表情、手指、准确焦距或光源参数。主体曝光/清晰度实时评分、更多硬件控制和复杂动态姿势尚未实现。

会话与照片保留在内存，刷新清空；无登录、数据库、社区或社交发布。示例全部为原创生成素材，无真实用户效果数据。设备兼容性、持续性能和需求价值需在真实互拍中继续验证。
